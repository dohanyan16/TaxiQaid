## Broker controls and configuration

The public endpoint accepts exactly `identifier` and `password` JSON, bounded to 4 KiB. Management usernames normalize to lowercase ASCII with no spaces/accents and remain stable after full-name changes. Approved unique suffixes belong to protected provisioning, not login. Driver identifiers are ten-digit Iqamas at the visible interface, but the verified schema has no driver/Iqama linkage yet. Numeric identifiers deliberately resolve to no identity without querying invented columns; provisioning remains future work. Only Supabase Auth verifies passwords; none are stored in custom tables or Sheets. Unknown/incorrect/disabled/unlinked cases use generic errors. Failed created sessions are revoked. A minimum randomized response duration reduces obvious timing differences; it is not a replacement for abuse prevention.

CORS uses exact approved origins. The protected SQL `begin_login_attempt` transaction consumes HMAC-hashed global/IP/identifier counters before resolving any private Auth identity and commits before official password verification. It reuses the existing security table; no runtime role has direct table access or a separate unthrottled resolver. See the [current review](USERNAME_LOGIN_BACKEND_REVIEW.md) for fixed-window/concurrency/outage/cleanup semantics, connection budgets, minimum column/RLS grants and reviewed secret **names**.

Readiness flags remain false/unset. The existing `TAXIQAID_DB_URL`/schema-mapping settings apply only to the older access candidate, **not** this broker. Do not change the proven deployed function's settings.

No trustworthy client-IP source has been established here. Header names or a readiness flag do not prove overwrite guarantees; every reachable ingress needs independent spoof verification. Missing/unreviewed IP, counter failure, TLS failure or database outage denies login. Native Auth is independently reachable and rate-limited; the publishable-key broker does not claim to forward end-user IPs or cover direct Auth attempts.

The login function needs public platform invocation (`verify_jwt=false`) because callers are not authenticated yet; its handler performs all required controls. `get-my-access` retains platform JWT verification and `auth:'user'`.
